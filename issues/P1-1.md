# P1-1 — Entity-encoded non-hidden tags survive into the output: …

## Finding / 问题

- EN: Entity-encoded non-hidden tags survive into the output: `toText("<p>&lt;b&gt;bold&lt;/b&gt;</p>")` → `<b>bold</b>`; `&lt;img src=x onerror=alert(1)&gt;` → a live `<img>` with an event handler; `&lt;a href=javascript:alert(1)&gt;x&lt;/a&gt;` → a live link. The README says the output "contains no tags … carries no injection risk".

  `&lt;img …&gt;`, `&lt;a …&gt;…&lt;/a&gt;`). Those were closed by the re-strip in `fb7094d` ("Strip the
  tags that entity decoding re-forms, not just hidden ones"). The additional fact is that an encoded tag
  which never gets a closing `>` **still survived verbatim after that fix**, e.g.
  `toText('<p>&lt;img src=x onerror=alert(1)</p>')` → `<img src=x onerror=alert(1)`. A missing `>` does not
  make it inert: a browser closes an unterminated tag at end of input, so it was live markup — the same
  leak the finding describes, in a shape the finding did not name.
  - Fixed in **`3856fe9`** ("Strip an encoded tag that was never closed"): `src/HtmlDigest.php:74` now ends
    the strip regex with `(?:>|\z)` instead of `>`, with `\z` rather than `$` so a trailing newline cannot
    stand in for the end of the string. Regression coverage: `tests/HtmlDigestTest.php`
    `testToTextStripsEncodedTagsThatAreNeverClosed`, plus the unterminated img/svg/a rows in the property
    list.
