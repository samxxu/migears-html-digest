# P3-3 — Second-pass tag-stripping regex breaks on > characters inside attribute …

## Finding / 问题

- EN: Second-pass tag-stripping regex breaks on > characters inside attribute values (e.g. onclick="x > 5"), leaving partial attribute text in output. Not a security issue — no live tags survive — but output may contain stray characters.
- 中文: 第二轮标签剥离正则在属性值包含 > 字符时（如 onclick="x > 5"）会断裂，输出中可能残留部分属性文本。非安全问题（无活标签残留），但输出可能含零散字符。
- Where / 位置: `src/HtmlDigest.php:128`
- Verification / 验证: static / 仅静态推断

## Thread

- 2026-09-28 · `reviewer — migears-full-review` · `open` — filed from the 5th round.
- 2026-10-01 · `owner — migears-html-digest` · `fixed` — re-graded P3 → P2: this is a silent
  wrong result (stray attribute text in the output), not the metadata/docs drift P3 names.
  Reproduced in a temp dir through the module's own `vendor/autoload.php`: `toText('<p>&lt;a
  href="#" onclick="x &gt; 5"&gt;link&lt;/a&gt;</p>')` returned `5">link`; also `b">caption`,
  `b">t`, `y">mid after`. Cause: the second-pass regex `[^>]*` stops at the first `>`, which
  inside a quoted attribute value is part of the tag, not its end. Fixed by consuming a quoted
  run before `>` can close the tag —
  `'/<\/?[a-zA-Z](?:"[^"]*"|\'[^\']*\'|[^>])*(?:>|\z)/'` (src/HtmlDigest.php:78). Those inputs
  now yield `link` / `caption` / `t` / `before mid after`. Regression test:
  `testToTextStaysTagFreeWhenADecodedAttributeContainsAngleBrackets` now asserts the exact
  output and fails without the fix (`'z'` vs `'y">z'`). The cited `src/HtmlDigest.php:128` is
  stale; the regex lives on line 78. Gates: phpunit 68 tests / 128 assertions green, phpstan
  clean, composer validate ok.
